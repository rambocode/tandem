# 产品官网宣传 SOP

本文把 Mole 官网的宣传结构抽象成一套可复用方法，并给出 Tandem 首页的落地映射。它关注的是“用户为什么愿意继续看、相信并下载”，不是复制 Mole 的视觉或文案。

## 一、先理解 Mole 为什么有效

Mole 不是按“公司介绍 → 功能卡片 → 联系我们”组织首页，而是沿着购买者的决策顺序推进：

1. **一句话给结果**：首屏先说能为 Mac 做什么，再给价格、平台要求与购买/下载入口。
2. **立刻展示产品**：大面积真实界面承担主要视觉，不靠抽象插画解释软件。
3. **先画产品地图，再讲细节**：先用“五个工具，一个入口”建立整体认知，再逐项解释清理、软件、优化、分析、状态。
4. **每项能力都说清边界**：不是堆功能名，而是说明会检查什么、会改动什么、默认如何保护用户。
5. **用多种证据建立信任**：产品截图、具体规则、用户评价、社区数据、更新日志、帮助文档共同作证。
6. **在用户犹豫的位置消除疑虑**：价格、退款、许可证、权限、安全性和竞品差异都放在决策链上。
7. **首页之外仍有完整内容系统**：帮助、文档、更新日志、博客、RSS、搜索、结构化数据与多语言页面共同承接长尾访问。Blog 保持纯阅读，用户反馈使用独立渠道，不把两种目标混在文章页里。

可以把这套结构概括为：

> 结果承诺 → 产品证据 → 能力地图 → 场景细节 → 信任证明 → 商业方案 → 疑虑消除 → 再次行动

## 二、标准内容准备

官网动工前先完成一张事实清单。所有页面文案必须能回到这里，避免宣传跑在产品前面。

| 内容类型 | 必须回答的问题 | 验收标准 |
| --- | --- | --- |
| 目标用户 | 谁最常遇到这个问题？ | 能用一句具体场景描述，而不是“所有用户” |
| 核心结果 | 用户最终得到什么？ | 先写结果，不先写技术实现 |
| 差异 | 为什么不用系统自带或竞品？ | 一到三条可验证的取舍 |
| 能力 | 产品实际可以做什么？ | 只使用已发布或明确可下载的能力 |
| 边界 | 它不做什么、需要什么条件？ | 平台、权限、网络和限制明确 |
| 证据 | 用户凭什么相信？ | 截图、演示、规则、数据、评价至少命中两类 |
| 商业 | 免费与付费如何区分？ | 价格、计费周期、设备数、退款口径明确 |
| 行动 | 用户下一步做什么？ | 主 CTA 直达可执行入口，少一步跳转 |

### 文案规则

- 标题写结果或任务，例如“截图、标注，转身就在 iPhone”，少写“强大、智能、高效”。
- 每个区块只回答一个购买问题；标题、正文、视觉和 CTA 必须围绕同一问题。
- 功能说明使用“动作 + 对象 + 结果”，例如“框选长网页，自动拼成一张完整图片”。
- 先说用户能感知的变化，再补协议、框架或算法。
- 不虚构评价、评分、客户 Logo、下载量、节省时间或性能数字。
- 尚未验证、仅开发中或存在明显限制的能力不得写成无条件承诺。
- 每个关键主张至少准备一种证据：产品画面、演示步骤、规则说明、更新记录或第三方评价。

## 三、标准首页结构

### 1. 导航：只保留决策入口

组成：品牌、三到五个页面锚点、语言入口、一个主 CTA。

导航不承担功能大全。锚点应对应购买阶段，例如“工作流 / 工具 / 隐私 / Pro / 常见问题”。下载按钮始终可见，但首屏主 CTA 仍应更完整地说明平台。

### 2. 首屏：五秒内回答四件事

首屏必须同时回答：

1. 这是什么；
2. 能为我完成什么；
3. 为什么它值得注意；
4. 我现在可以做什么。

推荐结构：

- 一句结果型主标题；
- 一段不超过三行的解释，包含产品类别和关键差异；
- 一个主 CTA、一个次 CTA；
- 免费/价格、平台要求等低风险说明；
- 一张足够大的产品主画面，能看懂核心工作流。

首屏不堆评价徽章、虚构数字、功能小卡或装饰性标签。产品画面应比装饰更醒目。

### 3. 硬证据条：把差异压缩成三句话

首屏后放三条最硬的事实，例如“仅局域网”“端到端加密”“买断无订阅”。它是快速确认，不是第二个功能区。

### 4. 场景闭环：让用户看到“我会怎么用”

用二到四个高频场景解释完整链路，而不是逐个解释按钮。每个场景按以下顺序写：

> 原来的麻烦 → 用户动作 → 产品响应 → 得到的结果

每个场景配一张独立、可读的产品画面。优先展示状态变化，不使用无关插图。

### 5. 能力地图：建立完整产品认知

把功能归并为三到五个稳定模块。模块数量要足以覆盖产品边界，又要让用户能记住。

每个模块包含：

- 一句任务型名称；
- 三到五条具体能力；
- 一张对应界面或交互演示；
- 一条限制、权限或安全说明（适用时）。

模块之间可以用标签切换、媒体轨道或错落版式，但不要重复同一种卡片网格。

### 6. 信任区：解释产品如何兑现承诺

隐私、安全和权限不能只写“安全可靠”。应说明：

- 数据经过哪里；
- 哪些数据不会上传；
- 何时需要权限；
- 历史或文件保存在哪里；
- 失败时产品如何降级或提示。

这一区域适合使用一张简洁架构图和三条可核实规则。

### 7. 商业区：减少计算成本

用户需要直接看到：

- 免费版能完成什么；
- Pro 多了什么；
- 总价格和计费周期；
- 是否订阅；
- 平台和设备要求；
- 购买或下载入口。

如果暂时没有可验证退款承诺，不要擅自添加。若购买入口尚未直达 checkout，应明确 CTA 当前会去哪里。

### 8. FAQ：只回答真实阻力

FAQ 优先覆盖：使用条件、账号、平台、权限、隐私、免费/Pro 差异、竞品或系统能力差异、失败排查。问题应来自搜索意图、反馈和售前沟通，不为凑数量而写。

### 9. 最终 CTA 与页脚

最终 CTA 重复核心结果和主行动，不引入新卖点。页脚承接对比、隐私、条款、更新日志、帮助与版本信息，让谨慎用户可以继续核验。

## 四、视觉与交互 SOP

- 选择一个明确视觉母题。Tandem 使用“设备接力轨道”：Mac、内容包和 iPhone 在同一条路径上移动。
- 一个主要区块只保留一个视觉焦点；真实或忠实的产品 UI 优先于抽象装饰。
- 长页面要交替使用开放留白、浅色内容区和深色信任区，避免每节都是居中标题加卡片。
- 同类媒体统一比例、圆角、阴影和裁切方式；不同区块通过尺寸和排列形成节奏。
- 文本与真实控件必须是 HTML，不能把 CTA、导航、价格或 FAQ 烘焙进图片。
- 动效只用于表达同步、切换和状态到达；支持 `prefers-reduced-motion`。
- 桌面首屏应露出下一段内容，让用户知道页面可以继续向下探索。
- 移动端优先保留标题、主 CTA 和核心产品画面；次要导航和装饰可以收起。

## 五、内容系统 SOP

首页是入口，不是全部内容。根据产品复杂度逐步补齐：

1. **更新日志**：证明产品持续维护；版本号与下载版本同步。
2. **对比页**：承接“替代品”“和系统能力有什么不同”等高意图搜索。
3. **帮助与文档**：承接权限、配对、同步失败和工作流细节。
4. **隐私与条款**：与官网承诺保持逐字一致。
5. **博客/指南**：回答用户在购买前就会搜索的问题，不只写产品公告；正文支持 Markdown、MDX 与受控 HTML，每篇文章只服务一个搜索意图，并自然连接到相关产品场景。
6. **SEO 基础**：canonical、hreflang、OG、JSON-LD、sitemap、robots。
7. **可访问性**：语义标题、键盘操作、焦点样式、对比度、减少动效。
8. **访问与转化统计**：用真实页面浏览、下载和订阅数据验证内容效果；第三方统计必须在隐私政策中说明数据边界，并由运营方按目标地区确定合规方案。

### Blog 运营闭环

每篇文章按以下顺序生产：

1. 从搜索问题、用户反馈或高频工作流中选择一个具体主题；
2. 明确读者、问题、搜索词和读完后的下一步；
3. 先给可独立使用的答案，再自然说明 Tandem 能缩短哪一步；
4. 使用真实产品能力、界面或可复现流程举证，不伪造数据；
5. 完成标题、摘要、分类、发布时间、阅读时长和语言字段；
6. 预览桌面与移动端，并检查 canonical、结构化数据、RSS 与 sitemap；
7. 发布后从更新日志、社交内容或外部软文回链，并根据搜索表现更新正文。

Blog 不开放文章评论，避免内容页被登录、审核和第三方脚本打断。用户意见在首页的独立反馈区收集；真实 App Store 评价形成后，再按可核验来源展示，不能用占位评价填充版面。

## 六、Tandem 首页内容映射

Tandem 当前没有足够的公开用户评价与可验证增长数据，因此本轮不用虚构社会证明，而是使用真实工作流、已发布能力、隐私架构和更新日志作为证据。

| 购买问题 | Tandem 回答 | 页面区块 |
| --- | --- | --- |
| 它帮我做什么？ | 复制、截图、标注后，内容可以在 Mac 与 iPhone 间继续使用 | Hero |
| 为什么不用传输助手？ | 同一局域网自动发现、点对点加密、无需账号与云端 | Proof strip / Privacy |
| 具体怎么用？ | 复制→手机粘贴；截图→标注→同步；录屏/OCR/长截图→导出 | Workflow |
| 它到底包含什么？ | 同步、截图、编辑、录屏、历史五个模块 | Toolkit |
| 会不会上传隐私？ | Bonjour 发现、设备直连、E2E、历史本地保存 | Privacy |
| 免费和 Pro 差在哪？ | 核心同步免费；Pro 增加文件、500 条历史和搜索 | Pro |
| 和系统能力有什么不同？ | 首页 FAQ 简答，对比页详细承接 | FAQ / Compare |

### 本轮页面顺序

1. Header
2. Hero：结果承诺、双平台 CTA、产品接力舞台
3. Proof strip：LAN / E2E / 免费核心与买断
4. Workflow：三个高频闭环
5. Toolkit：同步、截图、编辑、录屏、历史五个模块
6. Privacy：连接路径和三条规则
7. Pro：免费与 Pro 对照、价格与 CTA
8. FAQ
9. User feedback：独立于 Blog 的真实反馈入口
10. Final CTA
11. Footer

### 本轮事实边界

- 官网宣传以 `0.2.10` 更新日志已经发布的能力为上限。
- 可宣传：剪贴板双向同步、iOS 键盘和分享扩展、文件/图片传输、历史与搜索、区域/窗口/滚动/智能元素截图、OCR/二维码、主体抠图、屏幕录制、视频编辑、图片标注。
- 明示局域网要求、macOS 14+、iOS 16+、文件上限 50 MB、免费 20 条历史、Pro 500 条历史。
- 不宣传尚未出现在 `0.2.10` 更新记录中的 Mermaid、新建画布等后续能力。
- 本轮不增加未经确认的退款、设备数量、下载量、评分或用户评价。

## 七、发布前验收清单

### 内容

- [ ] 首屏五秒内能说清产品、结果、差异和行动。
- [ ] 所有能力都能在当前下载版本或更新日志中核实。
- [ ] 免费、Pro、价格、平台、网络和文件限制一致。
- [ ] 三种语言结构一致，没有只更新中文的漂移。
- [ ] CTA 均指向真实可执行入口。

### 视觉与交互

- [ ] 桌面与移动端首屏没有裁切、溢出和意外换行。
- [ ] 每个主要能力有可读的产品画面或交互证据。
- [ ] 页面区块节奏不重复，产品视觉不被装饰抢走。
- [ ] 模块切换、FAQ 和语言入口可用，键盘焦点清晰。
- [ ] 减少动效设置下不依赖动画理解内容。

### 工程与发现

- [ ] `npm run check` 无错误。
- [ ] `npm run build` 成功生成全部三语与子页面。
- [ ] canonical、hreflang、OG、JSON-LD、robots、sitemap 正确。
- [ ] Google Analytics 未配置时零请求；配置后全站加载且不出现额外弹窗，并能记录页面浏览与关键转化。
- [ ] 浏览器无相关 error/warn，主下载与 App Store 链接可达。
- [ ] 桌面和移动端都完成截图复核，首屏与主要工作流有交互证据。

## 八、迭代顺序

上线后按照“证据优先”继续增强：

1. 用真实产品截图或短视频替换忠实的代码化界面演示；
2. 收集经过授权、可追溯的用户评价，再增加社会证明；
3. 补配对、权限和常见故障帮助页；
4. 用真实流量与下载转化确定下一轮标题、CTA 和页面顺序，不以主观喜好频繁重排。
